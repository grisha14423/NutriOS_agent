# Health Coach Agent

Локальное Next.js-приложение для wellness-планов. Health Coach использует OpenRouter и выборочно читает профиль, дневник и рецепты через tools. Safety Reviewer оценивает план до его показа и сохранения.

Для вызовов модели используется OpenRouter Responses API. Health Coach работает через OpenAI Agents SDK, а Safety Reviewer сохраняет отдельный вызов `openai`.

Приложение не ставит диагнозы, не назначает лечение и не рекомендует лекарства.

## Настройка и запуск

Создайте `.env` в корне проекта и задайте параметры OpenRouter:

```env
OPENROUTER_API_KEY=ваш_ключ
OPENROUTER_MODEL=идентификатор_модели
```

Затем установите зависимости и запустите сервер разработки:

```powershell
npm install
npm run dev
```

Откройте `http://localhost:3000`. Для production используйте `npm run build`, затем `npm run start`. Не запускайте production-сборку одновременно с сервером разработки: оба режима используют `.next`.

## До MCP / После MCP

До MCP чтение профиля, дневника и рецептов, а также запись плана подключались к коучу отдельными функциями в приложении. Для каждой новой интеграции приходилось вручную описывать tool и его вызов.

После MCP эти данные доступны через локальный stdio-сервер `src/mcp/markdownHealthServer.ts`: пять tools и четыре resources. Harness запускает сервер для каждого запроса и закрывает его после завершения. Health Coach получает tools сервера через OpenAI Agents SDK. `suggestWorkoutTemplate` и `generateShoppingList` остаются локальными tools. Сохранение плана harness вызывает через MCP после одобрения Safety Reviewer. В UI и JSON-трейсе каждый вызов помечен `(mcp)` или `(tool)`.

Проверьте список tools и resources командой `npm run mcp:inspect`.

## Как работает приложение

1. Введите задачу в интерфейсе. Например: «Составь план питания на завтра с учётом моего профиля и дневника за последние два дня. Добавь лёгкую тренировку».
2. Health Coach решает, какие данные запросить. MCP предоставляет `read_profile`, `read_recent_logs` и `list_recipes`, а локальный tool `suggestWorkoutTemplate` предлагает тренировку.
3. Safety Reviewer получает только текст плана и возвращает вердикт, оценку от 0 до 10 и замечания. У reviewer-а нет tools.
4. При `revise` замечания возвращаются коучу вместе с историей его вызовов tools. Harness допускает до трёх раундов. Если reviewer одобрил план с оценкой ниже 7, harness просит коуча доработать его.
5. При `approve` и оценке не ниже 7 harness сохраняет проверенный план в `data/output.md`. Если задача включает список покупок, он создаётся в `data/shopping.md` из одобренного плана.
6. Вердикт `needs_human_professional` останавливает выдачу плана.

Чтобы использовать уже сохранённый план для покупок, попросите составить список к готовому плану, например: «Составь список покупок к сохранённому плану». Если сохранённого плана нет, приложение сообщит об этом. Для нового плана и покупок укажите оба действия, например: «Составь новый план питания на завтра и список покупок к нему».

В блоке «Что сделал агент» вызовы показаны по порядку с бейджем `mcp` или `tool`, статусом и длительностью. История раундов раскрывается отдельным списком, замечания Safety Reviewer выделены карточками. При ошибке интерфейс показывает уже выполненные вызовы и описание сбоя. В серверный журнал не записываются содержимое профиля и дневника.

## Как дебажить агента

Каждый запуск сохраняет JSON-трейс в `runs/`: задачу, модель, версии промптов, оценки по раундам и вызовы tools. При ошибке трейс содержит `verdict: "error"`, сообщение ошибки и уже собранные данные. Каталог исключён из git. Пример формата: `run-example.json`.

После изменения промпта или модели повторите задачу из трейса и сравните результаты, включая название модели:

```powershell
npm run replay runs/run-XXX.json
```

Чтобы последовательно проверить пять задач, включая раннюю остановку медицинского запроса, решение reviewer-а по медицинскому риску и вызовы tools для списка покупок, запустите:

```powershell
npm run eval
```

Скрипты читают параметры OpenRouter из `.env`. Replay и eval запускают агента заново; одобренный план может обновить `data/output.md`.

## Данные и основные файлы

- `data/profile.md` и `data/log.md`: личные данные, которые коуч читает только по запросу через tools.
- `data/recipes.md`: любимые рецепты, доступные коучу.
- `data/output.md`: последний одобренный план.
- `data/shopping.md`: последний список покупок.
- `prompts/`: версии инструкций Health Coach и Safety Reviewer.
- `src/mcp/markdownHealthServer.ts`: stdio-сервер для Markdown-данных.
- `src/skills/`: локальные tools для шаблона тренировки и списка покупок. Старые функции доступа к данным сохранены в файлах с суффиксом `-UNUSED.ts` и не вызываются.
- `src/harness/`: раунды проверки, порог безопасности и оркестрация вызовов.
- `app/api/agent/run/route.ts`: серверный endpoint `POST /api/agent/run`, принимает JSON `{ "task": "..." }`.

Профиль, дневник, сохранённый план и список покупок исключены из git.
